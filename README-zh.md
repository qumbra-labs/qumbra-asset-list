# qumbra-asset-list

> [English](README.md)

Qumbra 钱包按名字显示的 Annulet 资产，都登记在这份签名清单里。

在 Annulet 链上，一个资产就是注册表里的一个槽位，编号 1 到 65535。注册表叶子里存了 `issuer_key`、模式和几棵策略树的根，**但没有名字、代号和小数位**，这几样都从本仓库来。依据见 `qumbra-design` 的 `wallet-assets-decision.md`，D1–D3。

## 钱包遵守的规则

- **资产的身份是（创世哈希, 编号），不是名字。** 每个网络一份清单，文件名为 `lists/<创世哈希>.json`。创世哈希对不上的清单，钱包直接忽略。
- **清单必须签名。** 签名算法是 ML-DSA-65，签的内容是 `qumbra:asset-list:v1\0 ‖ 文件的原始字节`，签名文件 `<清单>.json.sig` 和清单放在一起，公钥放在 `keys/list-key.pub`。每个钱包版本都从本仓库某个锁定的提交里把清单和签名打包进去，再用编译进去的公钥验证。
- **清单钉住发行者公钥（D2）。** 只有链上注册表叶子里的 `issuer_key` 和清单写的一致，钱包才显示清单上的名字。发行者一旦轮换密钥，钱包就改为显示「发行方已变更」和原始余额，直到有新清单签出来。
- **清单里没有的资产照样显示**，写成「资产 #N」，用原始单位，钱包不会去猜它的小数位。
- **`testnet: true` 的清单**：它覆盖的每一行在所有界面上都标为测试币，包括列出的资产、没列出的资产和手续费单位。一份清单只对应一个网络，而一个网络要么是测试网，要么不是。

## 格式（v1）

见英文版。清单不得超过 1 MiB，解析规则很严格：

- 先检查 `v`，更高的版本按「版本不认识」拒收；
- 不认识的字段一律拒收；
- 编号必须递增，不能重复；
- 0 号（手续费单位）永远不上清单；
- 小数位不超过 18；
- 同一份清单里代号不能重复（不分大小写）。

解析器**不判断**名字像不像：形近字，或者一个并非 Tether 发行的「USDT」。这要靠本仓库在签名之前审查。

执行这些规则的就是钱包自己的解析器 `qumbra_wallet::asset_view::verify_asset_list`。下面的工具用的也是它，所以工具签出来的清单，每个钱包都会认。

## 新增或修改条目

1. 从节点读该资产的注册表叶子：`GET /v1/registry/<编号>`，第 49 到 81 字节就是 `issuer_key`。**十六进制值要从这次输出里复制，不能凭记忆填。**
2. 在 PR 里改清单。名字、代号、小数位要和发行方自己的说法核对一遍。
3. **持钥人离线签名**（见下），把 `<清单>.json.sig` 提交上来，CI 会验证。
4. 钱包要等某次发版重新锁定本仓库的提交，才会用上这次改动。

## 工具

用法见英文版：`keygen`（只做一次，离线）、`sign`（写出 .sig 后会自己再验一遍）、`verify`。

**种子文件就是签名私钥。** 它绝不能进本仓库（`.gitignore` 已拦住 `*.seed`），也不能放到服务器上或 CI 密钥里。请像保管发版签名密钥那样离线保管。
